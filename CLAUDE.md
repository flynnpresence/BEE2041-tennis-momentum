## Pipeline

Run the full pipeline:
```bash

```

Or step by step:
```bash
python3 scripts/download.py
python3 scripts/clean.py
python3 scripts/features.py
python3 scripts/model.py
python3 scripts/build_blog_data.py
```

### What each script does

**download.py** — Downloads 6 raw files from Jeff Sackmann's Match Charting Project and ATP/WTA match results repos. Saves to `data/raw/` unchanged. Includes a 1-second delay between requests per GitHub robots.txt compliance. Data licensed CC BY 4.0.

**clean.py** — Loads raw point-by-point and match metadata CSVs for ATP and WTA. Filters to 2023 Grand Slams main draw (drops qualifying rounds, junior events). Casts columns to pandas extension types. Merges points onto matches with `validate='m:1'`. Attaches official rankings via two-step join: primary GS-specific lookup, fallback season-median. Engineers the `High_Leverage` treatment flag and its components. Adds `focal_is_p1` random positional mask (seed 42). Creates `Next_Point_Won` outcome via `shift(-1)` within match groups. Outputs `atp_cleaned_points.csv` and `wta_cleaned_points.csv`.

**features.py** — Loads cleaned CSVs. Engineers strictly forward-rolling features within each match: `Streak_k4`, `Rolling_Win_Pct`, `CUSUM`, `BPOR`, `TBOE`. Runs per-player Chi-squared and Wald-Wolfowitz runs tests (77 ATP players, 78 WTA players). Outputs `processed_features.csv` (model checkpoint) and `per_player_tests.csv`.

**model.py** — Loads `processed_features.csv`. Runs cluster-robust logistic regression (clustered on `match_id`) and CausalForestDML (econml) separately for ATP and WTA. Runs causal forest three times per tour: combined treatment, break-point-only, tiebreak-only. Also runs a ranking-only robustness check. Saves 6 output files plus `outputs/ate_results.csv`.

**build_blog_data.py** — Reads `outputs/ate_results.csv`. Builds the `ATE` constant object and writes it to `blog_data.js`. Raises `ValueError` if any ATE value is non-finite. Must be rerun after every `model.py` run to keep the D3 chart in sync. **Never edit `blog_data.js` manually.**

## Key implementation details

### Break point detection — uses `.isin()` not `.endswith()`

Both `clean.py` and `features.py` use exact score matching:

```python
# clean.py — High_Leverage_BP flag
bp_p1_serving = (merged['Svr'] == 1) & merged['Pts'].astype(
    'string').isin(['0-40', '15-40', '30-40', '40-AD'])
bp_p2_serving = (merged['Svr'] == 2) & merged['Pts'].astype(
    'string').isin(['40-0', '40-15', '40-30', 'AD-40'])

# features.py — is_bp flag (identical logic, df not merged)
```

The previous `.str.endswith(('-40', '-AD'))` was wrong: it matched deuce ("40-40") and other non-break-point scores. Fixed to exact `.isin()` matching. This affects `High_Leverage_BP` (clean.py) and `is_bp` / `BPOR` (features.py).

### Tiebreak point detection — non-standard score strings

Tiebreak points use sequential counts (e.g. "3-2"), not standard tennis values {0,15,30,40,AD}. Detection splits on `-` and checks whether both sides are in the standard set; any non-standard score is a tiebreak point.

### Random positional mask

`focal_is_p1` is assigned randomly per match (seed 42) in `clean.py` to avoid double-counting every point from both players' perspectives. This seed must never change between runs — it determines which player is the focal player for the entire analysis.

### Outcome variable

`Next_Point_Won` is the outcome — whether the focal player wins the *next* point, not the current one. Last points in each match are dropped (no valid successor). Shift is applied within match groups after sorting by Set1/Gm1/Pt.

### Treatment definition

The treatment is winning a high-leverage point: `(High_Leverage == 1) & (Point_Won == 1)`. Break point and tiebreak sub-analyses use their respective flags (`High_Leverage_BP`, `High_Leverage_TB`) with the same won-point condition.

### Model configuration

```python
CausalForestDML(
    model_y=GradientBoostingRegressor(n_estimators=200, random_state=42),
    model_t=GradientBoostingRegressor(n_estimators=200, random_state=42),
    n_estimators=200,
    cv=2,
    n_jobs=1,
    random_state=42,
)
```

Stratified subsampling to 15,000 rows when data exceeds that threshold. SE computed as `cates.std() / sqrt(n)` — descriptive approximation.

### Controls

`['Focal_Ranking', 'Rolling_Win_Pct', 'Streak_k4', 'CUSUM']`

## Design constraints

- ATP and WTA are processed separately throughout — never pooled. Men's (best-of-5) and women's (best-of-3) formats differ too much to mix.
- No feature engineering in `clean.py` — only filtering, merging, ranking attachment, and the `High_Leverage` flag.
- All features in `features.py` are strictly forward-rolling (no look-ahead). `shift(1)` before every rolling window.
- Qualifying rounds excluded from the analysis.
- Junior matches excluded by name filter in `clean.py`.
- Seed 42 used everywhere for reproducibility.
